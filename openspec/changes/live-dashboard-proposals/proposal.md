## Why

Curator proposals and review decisions currently live in workspace files, so the swarm dashboard cannot show or review proposals generated by agents running against the centralized server. This leaves the live product blind to the knowledge-curation workflow and prevents remote review from becoming an auditable server-side operation.

## What Changes

- Define repository-scoped live proposal and review-decision contracts.
- Add explicit proposal publication from workspace/curator workflows to the live server.
- Store validated pending proposals and terminal review decisions server-side.
- Add live read APIs for proposal inventory and detail.
- Add live accept/reject APIs with idempotency and conflict semantics matching local review behavior.
- Add dashboard live proxy endpoints and enable Proposals navigation in live mode.
- Keep local filesystem proposal behavior unchanged.
- Enforce repository scoping, deterministic ordering, explicit reviewer metadata, and no silent overwrite.

## Capabilities

### New Capabilities

- `live-dashboard-proposals`: Server-backed proposal inventory, detail, publication, and review workflow.

### Modified Capabilities

- `dashboard-proposal-inbox`: Proposal list, detail, and review actions support a live server source.
- `live-dashboard-mode`: Proposals become available in live mode with explicit remote review semantics.

## Impact

- `crates/scryrs-server`: proposal/review persistence, validation, repository-scoped APIs, and conflict handling.
- `crates/scryrs-curator`: reusable publication and serialization contracts where current APIs are workspace-only.
- `crates/scryrs-cli` or curator workflow: proposal publication command/integration.
- `crates/scryrs-dashboard/src/server.rs` and frontend stores/views: live proxy and mode-aware review UI.
- Server database schema gains proposal and review artifact tables or equivalent versioned storage.
- Authentication/authorization must be addressed before enabling remote review writes; repository ID alone is not sufficient authorization for an untrusted deployment.
